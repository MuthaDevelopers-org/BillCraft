# Languages

## Status
- **English**: complete and the source of truth.
- **Hindi (हिन्दी)**: drafted, **not yet reviewed by a native speaker**. Review every string on the app screens, the printed bill and the WhatsApp message before relying on it.
- **Ten more** (Marathi, Gujarati, Bengali, Tamil, Telugu, Kannada, Malayalam, Punjabi, Odia, Urdu) are registered in `js/i18n/languages.js` but have no file yet. They are not offered in the picker until their `loader` is set.

## Add a language
1. Copy `js/i18n/locales/en.js` to `js/i18n/locales/<code>.js`.
2. Translate every value. Keep each key, and the placeholders in braces (`{name}`, `{number}`, `{words}`, `{lines}`, `{qty}`, `{currency}`, `{unit}`, `{rate}`, `{total}`), exactly as written.
3. Fill in `words`:
   - `zero` and `suffix` (the word for "only")
   - `units`: 100 entries, where index = the number 0 to 99
   - `hundred`, `hundredJoin`, `thousand`, `lakh`, `crore`
   The shared spelling logic is in `js/i18n/numberWords.js`. English uses `hundredJoin: ' and '`; Hindi uses `' '`.
4. Unit names (`unit.kg`, `unit.pcs`…) print on bills. Add each translated name, in lower case and without a final full stop, to that unit's `aliases` in `js/units.js`, so a unit typed in the language is recognised.
5. In `js/i18n/languages.js`, set the language's `loader` to `() => import('./locales/<code>.js')`.
6. Run `npm run stamp`, so installed copies download the new file, then `npm test`. The parity tests fail if a key is missing or extra.
7. Check the screens in a browser: the picker label, the step bar, the bill (PDF, PNG and print), the WhatsApp text and the payment reminder, and the dates (`formatDate` uses `<code>-IN` through `Intl`).
8. Ask a native speaker to review it, and keep the draft note in the file header until they have.

## What the tests enforce
- Every key in `en.js` exists in every locale file, and the other way round (`tests/i18n.test.js`).
- Every key used in `index.html` or any script exists, and every key is used (`tests/markup.test.js`).
- Every standard unit has a name in every language, and that name reads back as the same unit (`tests/units.test.js`).
- Every `placeholder`, `title` and `aria-label` in `index.html` has a `data-i18n-*` key, and every `<option>` a `data-i18n` key. Number-only placeholders such as `0` are the exception.
- The start-up failure message in `index.html` is plain English and Hindi on purpose: it must work when no script runs. Add a line for a new language there too.

## Right-to-left (Urdu)
The registry already marks Urdu `dir: 'rtl'`, and the page sets `<html dir>` from it. The layout has not been audited for RTL, so expect fixes when the Urdu file is added.

## Fonts
The app serves only its Latin font (Plus Jakarta Sans, `fonts/`). Hindi and other scripts use the device's own fonts: Noto on Android, Kohinoor on Apple devices, Nirmala UI on Windows. They are named in `--font-sans` in `css/variables.css`. Nothing is loaded from Google Fonts or any other site, because the Content Security Policy allows only this site.

If a language shows empty boxes on some device, add a woff2 subset of a Noto font for that script to `fonts/` with its licence, an `@font-face` rule in `css/base.css`, and the family to `--font-sans`. Then run `npm run stamp`.

## Amounts in words
English output is unchanged from the original app (`numberToWords`). Other languages use the `words` block of their locale file through `createTranslator().words()`.
